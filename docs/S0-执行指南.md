## Day 4 · 第一次调用大模型

**目标**：调通 API，并真正理解"消息"和"参数"。

**知识点**
- **消息角色**：`system`（设定人格/规则）、`user`（用户说）、`assistant`（模型说）
- **token**：模型按 token 计费和计数，中英文 token 划分不同
- **上下文窗口**：能塞进去的最大 token 数，超了就报错或截断
- **temperature / top_p**：采样随机性，越低越稳定、越高越发散
- **流式输出**：逐块返回，改善"首字延迟"体验
- **幻觉**：模型会一本正经地编，需要用工具/检索给它"事实依据"

**练习**：打开 `examples/s0/02_llm_structured.py`，补完 `classify()`：
- 让模型把用户一句话分类成意图，并**只输出 JSON**；
- 用 Pydantic 把它解析成对象。

```bash
uv run python examples/s0/02_llm_structured.py
```

**验收**：能拿到结构化的 `Intent(intent=..., confidence=..., reason=...)` 对象。

> 这一步你已经在用"结构化输出"了——它是后面 S4 意图识别的雏形。

## LLM 概念卡（必须能口头解释）

| 概念 | 一句话解释 |
|---|---|
| token | 模型处理文本的最小单位；计费和长度限制都按它算 |
| 上下文窗口 | 一次能看进去的最大 token 数，超出会被截断或报错 |
| temperature | 采样随机性；0 附近稳定可复现，1 附近发散有创意 |
| system / user / assistant | 三种角色消息：设定规则 / 用户输入 / 模型回复 |
| 流式输出 | 逐块返回文本，降低首字等待，观感更流畅 |
| 幻觉 | 模型生成看似合理但实际错误的内容；靠工具和检索来抑制 |
| 成本 | ≈ 输入 token 数 × 单价 + 输出 token 数 × 单价 |
| 结构化输出 | 用 JSON Schema 约束模型返回格式，便于程序解析 |

## 卡住了怎么办（这套方法比答案更值钱）

1. **先读报错的最后一行**——90% 的问题它已经告诉你了。
2. **做最小复现**：把出错代码砍到只剩 5 行，看还错不错。
3. **让 AI 解释，别让它代写**：问"这段代码为什么报错""这行是什么意思"，而不是"帮我写完"。
4. **写进笔记**：现象 → 排查 → 根因 → 解决。第 8 周面试时，这些就是你最真实的素材。
5. **卡超过 40 分钟就换一个方向**：先跳过，去做别的，回头再看往往就通了。
