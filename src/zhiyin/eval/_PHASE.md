# [S8] 评测飞轮 —— 本目录你要写什么

**目标**：把"感觉还行"变成"数据说话"。

## 要实现的文件 / 目录
| 位置 | 内容 |
|---|---|
| `datasets/` | 测试集：100 条 case，覆盖【可答 / 歧义 / 过期信息 / 应拒答】四类，附人工标注 |
| `metrics.py` | 封装 RAGAS（Faithfulness、Answer Relevancy、Context Precision/Recall）与 DeepEval（任务完成率） |
| `run_eval.py` | 一键跑评测，输出 JSON / Markdown 报告 |

## 指标（建议的"北极星"）
- **任务完成率**（Agent 侧核心指标）
- **Faithfulness**（RAG 是否基于检索内容，防幻觉）
- **P95 延迟 / 单次成本**（工程指标）

## 动手步骤
1. 建测试集（先 30 条，逐步扩到 100）。
2. 跑基线，记录数字。
3. 做**坏案例归因**：把失败分类到【解析 / 检索 / 重排 / 生成 / 工具】。
4. 针对 Top 失败原因做一次定向优化，再跑评测，证明提升。
5. 接入 CI（GitHub Actions），指标跌破阈值则失败。

## 验收标准
- [ ] 一条命令跑完评测并出报告
- [ ] 有一份"v1 → 归因 → v2"的迭代报告，指标提升可量化

## 常见坑
- 没有测试集，全靠手感调 prompt
- 只用 LLM-as-judge 不做人工抽样校准
- 指标一大堆却没有北极星
